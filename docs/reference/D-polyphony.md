# Polyfonie

Ithaca udržuje pool až 128 (max 256) nezávislých hlasů (`Voice`), z nichž každý přehrává jeden `SampleAsset` přes první mikrofon (`mics[0]`). `VoicePool` rozhoduje o alokaci, retrigger-dampování a krádeži hlasů; `patch_manager` vybírá konkrétní `SampleAsset` a velocity-gain pro danou (nota, velocity) kombinaci. Hlas sám řídí tři navrstvené envelopy (onset anti-click, release, underrun-fade), damping crossfade při retriggeru/krádeži a lineární interpolaci při přehrávání z preload-head i streamovaného ringu. Streaming (vlastnictví ringu, lo/hi interpolační okno, refill heuristika, bulk čtení ringu) žije ve sdíleném `StreamedSampleReader` (`engine/stream/streamed_reader.{h,cpp}`, viz [C-buffers](C-buffers.md)) — Voice drží jen POLICY při prázdném ringu (čistý konec vs underrun). Damp buffery všech hlasů leží v souvislém `VoicePool::damp_pool_` (Voice drží jen pointer) — `sizeof(Voice)` je díky tomu ~stovky B místo ~16,5 kB.

(5) Při deaktivaci `reader_.release(stream_)`. Návratová hodnota: `active_ || damping_ || produced` — hlas zůstává zpracováván dokud doznívá damping crossfade i po deaktivaci (`VoicePool::processBlock` dampující hlasy nepřeskakuje). ## Křížové odkazy

| Oblast | Vazba |
|--------|-------|
| **Events — noteOn/Off zdroj** | `Engine::processBlock` drainuje lock-free MIDI frontu a volá `selectVoice` + `VoicePool::noteOn` / `noteOffWithPedal` / `releasePendingNotes` / `allNotesOff`. (`VoicePool::noteOff` je test-only API — Engine ho nevolá.) Hlasy tedy vznikají vždy na audio threadu, i když MIDI event přidal jiný thread. |
| **Buffers — streaming ring** | Veškerý streaming jde přes sdílený `StreamedSampleReader` (`reader_` member, viz [C-buffers](C-buffers.md)): `Voice::start` → `reader_.begin` (acquire ring + první request); `Voice::process` → `reader_.beginBlock`/`endBlock` (bulk čtení: 1 acquire + 1 release za blok místo per-frame `popFrame`) + `reader_.refill` (requestRead vrací bool, při plné frontě se offset neposouvá); `Voice::prepareDamp` a `hardStop` vracejí ring (`reader_.release` → `releaseRing` — dělá gen bump, viz oblast C). Ring je sdílený zdroj — main pool má `EngineConfig::num_rings` slotů (default 256, vždy ≥ počtu hlasů); při selhání acquire (`begin` vrátí false) hlas degraduje na preload-only režim. |
| **Loader — Bank / sample_types** | `selectVoice` přijímá `const Bank&` (struktura `NoteSlots`, `VelocitySlot`, `SampleAsset` definované v `engine/sample/sample_types.h`). `Voice::start` ukládá `const SampleAsset*` a `const MicLayer*` (mics[0]); následně čte `mic_->preload_head`, `mic_->head_frames`, `mic_->file.frames`, `mic_->file.sample_rate`, `mic_->file.path`, `mic_->mode`. Při reloadu banky `VoicePool::reset` (hard-stop všech hlasů) musí proběhnout PŘED uvolněním staré banky paměti. |
| **Resonance — eligibility `hasActiveMainVoice`** | `ResonanceEngine::onPlayedNoteOn` volá `VoicePool::hasActiveMainVoice(N)` jako součást eligibility filtru (spec 5.5.1 pravidlo 1): rezonanční hlas pro notu N je ineligibilní, pokud pro midi=N žije hlavní hlas (zahrnuje held, releasing i pedal-sustained stavy). Od feat/async-loader-a-stream-refactor je test O(1) přes per-nota čítač `note_active_count_`. |

## Nálezy revize

### Osiřelý damping crossfade (retrigger/steal NENÍ click-free) — ✅ VYŘEŠENO (fix/revize-2026-06-10)

Původní nález (revize 2026-06-10, §1.5, VYSOKÁ): `prepareDamp` deaktivoval hlas (`active_ = false`, `damping_ = true`), ale `VoicePool::processBlock` dampované hlasy skipoval (`if (!v.active()) continue;`). Damp ocas se přehrával jen když `findSlot` náhodou vrátil tentýž slot. Jinak: (a) starý průběh noty byl tvrdě uříznut = lupnutí; (b) osiřelý `damp_buf_` zdědil pozdější nesouvisející noteOn na tom slotu → až 21ms "duch" staré noty.

Řešení: nový getter `Voice::isDamping()` a podmínka v `VoicePool::processBlock` — přeskakují se jen hlasy, které nejsou `active()` ANI `isDamping()`. Damp ocas po `prepareDamp` tak dozní VŽDY a v reálném čase, i když nový hlas dostal jiný slot. Tím mizí i "ghost" scénář: ocas se nedrží zamrzlý do příštího noteOn, ale přehraje se hned (≤ 21 ms po retriggeru/stealu); pokud noteOn dorazí na tentýž slot ještě během doznívání, ocas pokračuje souběžně s novým hlasem — což je přesně zamýšlený crossfade. `start` damp stav resetovat nemusí.

### Underrun rozlišování — heuristika `file_request_off_` — ✅ VYŘEŠENO (fix/revize-2026-06-10)

Původní nález: čistý konec vs. skutečný underrun se rozlišuje porovnáním `file_request_off_ >= total_frames`; `file_request_off_` se ale navyšoval i při dropu requestu (plná fronta) → skutečný underrun se mohl klasifikovat jako "čistý konec" (žádný `noteUnderrun()`, framy se už nikdy nedožádaly).

Řešení: `StreamEngine::requestRead` vrací `bool`; při `false` (drop-on-full) se offset NEPOSOUVÁ a refill heuristika request přirozeně zopakuje příští blok (logika dnes žije ve sdíleném `StreamedSampleReader::begin`/`refill`). `file_request_off_` tak roste jen o skutečně zařazené requesty a heuristika je spolehlivá (`cleanEnd()`). Chování při rozlišení: čistý EOF → deactivate+zero s 5ms fade (Info END-OF-SAMPLE, reference icr); skutečný underrun → drží poslední známý vzorek a 5ms fade ho tvaruje (Warning + `noteUnderrun()`).

### Výkonový nález — 16 kB damp buffer inline, O(pool) `hasActiveMainVoice`, 3 atomiky na frame — ✅ VYŘEŠENO (feat/async-loader-a-stream-refactor)

Původní nález (revize 2026-06-10, §2 oblast D, STŘEDNÍ): (a) `sizeof(Voice)` = 16 528 B (16 kB `damp_buf_` inline) → všechny skeny poolu (`processBlock`, `findSlot`, čítače) krokovaly cache po ~16,5 kB; (b) `hasActiveMainVoice` byl O(pool) scan volaný až 127× na jeden note-on z rezonanční eligibility; (c) hot-path čtení ringu dělalo 3 atomické operace na KAŽDÝ frame v `popFrame`.

Řešení (větev `feat/async-loader-a-stream-refactor`):
- (a) damp buffery přesunuty do souvislého `VoicePool::damp_pool_` — Voice drží jen pointer (`setDampBuffer`, pointery přidělené po resize, žádná realokace) → `sizeof(Voice)` ~stovky B; test v `test_voice_pool.cpp` hlídá `sizeof(Voice) < 512`.
- (b) per-nota čítač `note_active_count_[128]` → `hasActiveMainVoice` O(1); ekvivalenční test proti ground-truth scanu v `test_voice_pool.cpp`.
- (c) bulk čtení ringu: `RingHandle::snapshotW/cursorR/commitR` + `StreamedSampleReader::beginBlock/endBlock` — 1 acquire + 1 release za blok, bit-exact shodné s per-frame `popFrame` (viz [C-buffers](C-buffers.md)); bit-exact chování celé render cesty hlídá `tests/test_render_regression.cpp`.

### `processBlock` ignoruje `engine_sr` parametr

`VoicePool::processBlock` přijímá `engine_sr` ale okamžitě provede `(void)engine_sr` a nepředává ho do `Voice::process`. `Voice::process` `engine_sr` fakticky nepotřebuje (vše per-frame je vypočteno při `start`/`release`), takže to není bug — ale signaturu lze zjednodušit a zbavit se mrtvého parametru.

### Envelope sekvencování — release-v-onsetu spojitý (aktualizováno fix/revize-2026-06-10)

Onset, release a underrun-fade jsou nezávislé rampy nasazované multiplikativně. `release` startuje VŽDY z `rel_gain_ = 1.0` a onset rampa dobíhá dál — součin onset×release je spojitý (dříve `rel_gain_ = onset_gain_` při release-v-onsetu → v `process` se násobily obě rampy → skok g0 → g0² = klik při staccatu; opraveno). Přidaný guard `release_ms ≥ 0.1` (0 by dalo −inf step). `prepareDamp` snímá do damp bufferu obálku včetně `onset_gain_` (steal během náběhu bez skoku). Pedal pending-release je při retriggeru správně čištěný (`pending_release_ = false` ve `start`).
